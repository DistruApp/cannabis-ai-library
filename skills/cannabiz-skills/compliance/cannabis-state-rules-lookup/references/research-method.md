# Live research method

Use this only when the state profile doesn't cover the question or might be out of date.

## Source priority

What's *required* is set by the operative text of the current regulation or statute. Guidance explains how to comply with it.

1. **The current rule text on the regulator's own rules page.** Often a PDF compilation; say if it calls itself unofficial. Regulator URLs are listed in `state-profiles.md`.
2. **The official administrative code, register or legislature site.** Use it to confirm the version and to catch amendments the regulator's page doesn't show yet.
3. **Regulator guidance, FAQs and advisories, and official traceability guidance.** For Metrc states, that state's Metrc bulletins (archive at https://www.metrc.com/information-and-materials/bulletin-archive, filtered by state code) and the state partner page `https://www.metrc.com/partner/{state}/`. These explain *how*; the regulation sets *what's required*. Cite them alongside the rule, never instead of it, and compare their date with the rule's effective date: guidance older than the current rule may be out of date. Cite both when they differ.
4. **Secondary sources** (law-firm alerts, Cornell LII, trade press). These are only for *finding* the primary source. Cite one only if the primary source can't be reached, and label it "secondary source".

Stop when you have the operative sentence, its effective date or version, and have checked the regulator's rules page for a later amendment or open rulemaking on the topic. If guidance or a secondary source is all you could reach, the requirement stays NEEDS VERIFICATION.

Never cite: AI-generated summaries, vendor marketing copy (except to say which vendor a state uses, labeled "Vendor-only"), or forum posts.

## What to record for every rule

| Field | Example |
|---|---|
| Citation | 4 CCR §15051 |
| URL | https://www.cannabis.ca.gov/cannabis-laws/dcc-regulations/text-of-regulations/ |
| Exact operative text | "…at least once every 30 calendar days…" |
| Effective date / version | Compilation in effect as of 2026-10-01 |
| Accessed date | 2026-10-16 |
| Official vs. unofficial | Unofficial compilation; official text is in the CCR |
| Pending changes found | DCC-2026-02-R (text not reviewed) |

## If a site blocks access

Several state sites block automated access. As of 2026-11-11: med.colorado.gov and its new home sbg.colorado.gov/med, sos.state.co.us, michigan.gov (including michigan.gov/cra), legislature.mi.gov, ilga.gov and cannabis.illinois.gov. As of 2026-10-16 also: azdhs.gov, commerce.alaska.gov, com.ohio.gov. The exact pages a person should open are listed under **Blocked sites (open in a browser)** in `state-profiles.md`. Don't fill the gap from memory. Tell the user which page to open and what to look for. You can give what `state-profiles.md` already holds, with its label and source version (a verification-only answer, see SKILL.md step 2). Anything the profile doesn't hold stays NEEDS VERIFICATION, with no period, count, deadline or threshold, until they confirm it.
