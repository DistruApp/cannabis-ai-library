# Release report: v0.3.0 (2026-11-11)

Commit: `9f3e1d7` (evals ran on `28f503b` and earlier commits; the two commits after it change only the changelog and the CI runner). Prepared by: release owner, with Claude Code. Process: the release process in the internal staging repo.

## Decision

**Approved for release as v0.3.0.** Gates 1, 2 and 5 pass. Gate 4 has one blocking miss, accepted as a known limit below. The repository is already public: the owner made it public on 2026-11-11 so the website link would work. This report records where each gate stands on that code.

On 2026-11-11 the release owner asked Claude Code to decide the open items. The decisions:
- **Compliance sign-off (Gate 3):** release without it, as a known limit. Every state-profile item carries its verification label, and the skills send users to the regulator to confirm. The compliance lead's sign-off stays open and goes in the table below when given.
- **No real-data trial for precheck, harvest yield and batch COGS:** accepted. The test account has no manifests, harvests or batch costs to run them on. Script tests (Gate 2) and synthetic evals (Gate 4) cover them. Trial them when a test account with that data exists.
- **Expiring-inventory dashboard:** the Claude browser check on 9f3e1d7 is accepted for this release. A person should still look before it's demoed, but that doesn't block the release.
- **Staff scheduling e5:** accepted as a known limit. It's a skill-loading miss, not a wrong figure or a safety failure: the answer (4 packagers) is right and nothing is published. In about 1 run in 3, Claude answers a one-line "how many packagers?" question itself and doesn't ask for the roster. Fix it in the next release with a description change tested against e5 and the negative triggers.
- **Where release reports live:** in this repo, next to the Gate 3 reports already here. The real-data trial report has the test account's licence numbers removed.
- **Test-account data:** stays out of the public repo. `plugin-evals/trial/` stays local and gitignored, so the trial cases can't be re-run from a fresh clone.
- **GPT agents through pi:** stay without Bash. Cases that run scripts stay on `claude plugin eval`, which runs them in its sandbox.
- **All 10 skills stay public.**

**What the failures were, and what changed.**
- **Wrong expected answers (graders fixed):**
  - Scheduling e1 expected 180 required hours. With the even open/close split both models state, Friday close needs 2 people, not 3, so the right figure is 174.
  - Scheduling s1 accepted the open gap only on Sunday close, though either Sunday shift is valid.
  - Scheduling e5 now also accepts "120 units per packager into 480", the same working as 24 worker-hours ÷ 6.
- **Wording checks too narrow (graders fixed):**
  - Scheduling s1 read "I scheduled Tom Wed–Sat" as a send claim.
  - Inspection s2 didn't accept correct wording such as "I haven't confirmed" or "could not be verified".
- **Skill gaps (skills fixed):**
  - Inspection readiness: now moves whiteboard waste notes into the log as late entries, and no longer rates unchecked items as Critical.
  - SOP trainer: no longer writes a review waiver into the SOP when asked to skip review, and no longer puts record-keeping steps the operator didn't describe into the procedure.
  - Batch COGS: now asks whether in-house flower is costed at the transfer cost or the cultivation cost in the same combined question.
  - State rules and inspection: now write the NEEDS VERIFICATION label word for word.
- **Skill not loading:**
  - Inspection readiness now names missing or backdated records in its description. Before, Claude answered the backdating request (e4) itself in 3 of 3 runs; on the final run it loaded the skill in all 3.
  - State rules now names requests to draft or send a regulator notice (e6).
  - Staff scheduling now names sizing a crew from a unit target and an hourly rate. Even so, it still misses e5 in about 1 run in 3, which is the open case.
- **Environment:** one reconciliation s3 run couldn't reach its script because of the sandbox. The skill stopped instead of computing by hand, which is correct, and the case passed on the next run.

**Coverage limits.** COGS s4, the case where the script is unavailable, last ran on c1623a0. COGS later gained one sentence on missing flower cost, and s4 wasn't re-run. Two replenishment positive-trigger cases didn't load the skill on their single run at f3c59b4 and are flagged for review:

## Known limits shipped (release notes)

- **Compliance lead sign-off (Gate 3) is open.** Until then, the state profiles are a researcher-checked pointer to the rules, not a compliance-approved source. Every item carries its verification label.
- **Not trialled on real data:** manifest precheck, harvest yield and batch COGS. They are covered by script tests (Gate 2) and synthetic evals (Gate 4) only.
- **Expiring-inventory dashboard:** its data model is tested in Node. On 9f3e1d7 a Claude session opened it in the desktop app's browser and found no defects:
  - no console errors;
  - headline figures consistent with the matrix ($33.9K; Mango 1,365 units × $17.50 = $23.9K);
  - the offer panel and promo brief work, with unset recipient, deadline and sender left as asks and "do not send" in the brief;
  - the 18-month toggle works, running to May 5, 2028;
  - no sideways scrolling at 375px.

  In dark mode it keeps a light body with a dark hero, as `reference-dashboard.md` specifies. A person should still look at it before it's demoed; that doesn't block this release. The upstream template it was built from isn't in this repo, so a rebuild from it would undo these fixes. The demo video predates the fixes.
- **Staff scheduling, one-line crew questions (Gate 4 e5):** in about 1 run in 3, Claude answers "how many packagers?" without loading the skill. The figure is right, but it doesn't ask for the roster before anyone is assigned.
- **Connected Distru evals:** expiring inventory's numeric behaviour with a live connector was trialled once by hand. There's no automated Distru mock yet.
- **SOP trial:** needs a scripted second turn (approve Phase 1) to grade the full SOP.
- **State-profile wording, P2, not applied:**
  - MA 500.105(13) recipients;
  - IL IB-2025-03 still to be confirmed on the regulator's site;
  - IL DCC-2026-02-R/03-R;
  - IL 1300.810(a) vs (b);
  - the Bulletin 18 step.
- **Other open P2s** (fix logs, "Open items"):
  - reconciliation's `input_problems` are strings, not structured records;
  - precheck row numbers after blank lines;
  - replenishment applies no MOQ (it only flags it), and its new-SKU heuristic can shorten very intermittent sellers;
  - the COGS trigger fix (C8) is covered by the trigger evals but hasn't had a fresh-session real-data trial.
